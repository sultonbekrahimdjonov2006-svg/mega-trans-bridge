# AI Fashion

AI Fashion — будущая premium-платформа для магазинов одежды. Её ключевой продуктовый сценарий — **AI Продавец**: доброжелательный помощник, который помогает найти одежду, подобрать образ и в дальнейшем покажет, как вещи могут выглядеть на пользователе до покупки.

## Текущий статус — Task 01

Создан фундамент клиентского приложения и первый рабочий экран AI-продавца. Реальные AI API, платежи, пользовательские фотографии, заказы и production-база данных намеренно не подключены.

### Реализовано

- Next.js App Router, React, TypeScript в строгом режиме, Tailwind CSS, ESLint и Prettier.
- Масштабируемая структура, разделяющая routes, feature-модули, UI-примитивы, типы и утилиты.
- Премиальный адаптивный чат AI Продавца с демонстрационным приветствием, статусом, загрузкой и локальной отправкой сообщений.
- Поле ввода, меню действий `+`, кнопки фото и микрофона — готовые UI-точки для будущих интеграций.
- Mock-карточки товаров с размерами, наличием, ценой и действиями «Примерить»/«Подробнее».
- Базовые accessibility-практики: семантические элементы, подписи, keyboard focus, доступные имена кнопок и live-region состояния.

## Стек

- **Next.js 15** / **React 19**
- **TypeScript** (strict)
- **Tailwind CSS**
- **ESLint** / **Prettier**
- **lucide-react** для иконок

## Быстрый старт

Требуется Node.js 20.9+ и npm.

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

## Команды

```bash
npm run dev            # локальная разработка
npm run build          # production-сборка
npm run start          # запуск production-сборки
npm run typecheck      # проверка TypeScript
npm run lint           # ESLint
npm run format:check   # проверка форматирования
npm run format         # автоформатирование
```

## Структура

```text
src/
├── app/                 # Next.js routes, layout и глобальные стили
├── components/ui/       # переиспользуемые UI-примитивы
├── features/chat/       # функциональный модуль AI-продавца
├── lib/                 # общие утилиты
└── types/               # доменные контракты
```

Архитектура готова к выделению клиентского приложения, admin/store dashboard, backend/API, AI services и shared-пакетов. Интеграции должны оставаться provider-neutral; каталожные, заказные и reservation-данные в будущем получают границу магазина (`storeId`) для multi-store сценария.
